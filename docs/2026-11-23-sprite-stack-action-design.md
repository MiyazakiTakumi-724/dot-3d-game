# sprite stackingの見下ろしアクション：設計メモ（2026-11-23）

## 目的と理由
- sprite stacking（輪切りドット絵を重ねて立体に見せる手法）を使った、3Dに見えるドット絵の見下ろしアクションを作る。
- 3Dであることを活かすため、「高さ」をゲームの仕組みの中心にする。
- 本格的に作り、うまくいったらSteamでリリースする。

## ゴール
- 見下ろし視点で、ステージごとに武器が1つずつ増えるアクションゲーム。
- 武器（増える順番）：
  1. 鉄球：目の前に落とすことしかできない。落ちる高さでダメージが変わる。
  2. 剣：近接攻撃。
  3. 弓：チャージしないと弱い。
  4. エアガン：弾数制限あり。
- 高さの仕掛けはまず2つ：登れる段差、隠れられる壁。
- 各ステージの目標：小さなマップの敵を全滅させる。

## やらないこと（今回の範囲外）
- FPSのような一人称視点・肩越し視点。
- 大きなオープンマップ（ステージは小さく区切る）。

## アンチゴール（動いても失敗とみなすもの）
- 高さが見た目だけで、遊びに関係しない。
- 見た目がドット絵らしくなくなる（拡大でぼやける、ジャギーが崩れる）。

## 制約
- エンジン：Godot（GDScript）。ユーザーの選択。
- 配布先：Steam（PC）。
- 開発者は1人、ゲーム制作は初めて。Webフロントエンドの経験はある。

## 作り方の候補（検討した案）
- Godot（採用）：無料で使用料もかからない。sprite stackingの作例が多く、PC/Steam向けの書き出しがそのままできる。
- ブラウザ（TypeScript）：Webの知識が活きるが、Steamで出すにはアプリに包む手間がかかり、ゲーム向けの仕組みを自前で用意する部分も多い。
- Unity：情報量は最多だが、2Dの小規模ゲームには重い。重ね絵を大量に描く処理には工夫が要る。
- ユーザーは「リリースしたい」という目標に一番近いGodotを選んだ。

## ユーザーが決めたこと
- 見下ろし視点、高さを活かすアクション（案3）。
- 武器の内容と、ステージごとに増える構成。
- 段差と壁から始める（提案をそのまま採用）。
- ステージ目標は敵の全滅（提案をそのまま採用）。
- Godotを使い、Steamでのリリースを目指す。

- 最初のゴールは「鉄球だけの1ステージ」を遊べる形にして面白さを確かめること。4ステージ全部はその後。
- 鉄球は落としたら拾い直す（回数無制限ではない）。
- 上り下り：ジャンプなし。段差に近づくと自動で登るが、登れるのは1段まで。飛び降りは3段まで。後でアイテムでこの上限を変えられるようにしておく。
- 「隠れられる壁」は敵の弾を防ぐ盾（ステルスはやらない）。
- 敵は最初は平らな所を歩くだけ。高さを使う敵は後のステージで足す。
- 輪切りのドット絵素材はユーザー自身では作らない。

## こちらで決めたこと（提案・修正可）
- 素材の調達：試作では、ボクセルの形をコードで定義して輪切り画像を自動で作る（色付きの箱や簡単な形）。リリース版の素材は、商用利用できる配布・販売素材を使うか、イラストレーターに依頼する。どちらにするかは試作で面白さを確かめた後に決める。
- 高さは「段」単位の整数で扱う（1段＝輪切り何枚分かは作る人が決める）。鉄球のダメージは落ちた段数で決まる。
- カメラはプレイヤーが回せるようにする（sprite stackingの見どころ）。
- 解像度は低めに描いて整数倍で拡大し、ドット絵らしさを保つ。

## 作る人に任せること
- sprite stackingの描画方法（Godotでの実装の仕方）。
- 当たり判定や高さの内部表現。
- フォルダ構成やシーン構成。

# 試作3「大陸のエリアをつなぐ」設計

日付：2026-11-24（ユーザー承認済み。実装済み：計画 `docs/superpowers/plans/2026-11-24-world-areas.md`）
前提：`docs/design.md`（全体の仕様）、`docs/superpowers/specs/2026-11-23-death-loop-design.md`（試作2。墓石・たき火・門・持ち物の扱いはここから引き継ぐ）。

表記のルール
- 印がない項目は、ユーザーが決めたこと（Claudeの提案をユーザーが「それでいい」と承認したものを含む）。
- 【Claudeの判断】が付いた項目は、ユーザーに聞かずにClaudeが決めたこと。ユーザーが読んで直せるように印を付けている。

この設計は、試作2の設計メモと食い違う所では、こちらを優先する。

## 1. 目的と理由

試作2の箱庭の島を遊んだユーザーが、「マップがイメージと違う。開発より先にイメージをまとめよう」と言った。ユーザーのイメージは次のとおり。

- ステージごとにクリアする作りではない。1つの大陸が、いくつものエリアに分かれている。今いるエリアだけを描く。一昔前のモンハンのフィールドに近い（エリアの端まで歩くと、となりのエリアに切り替わる）。
- エリアごとのクリアはない。
- プレイヤーは、より強い敵・装備・素材を求めて探検していく。
- 高さはシステム的にもっとこまめに変わってほしい。今の島は少し見にくい。
- 鉄球などのアイテムは、マス目で選ぶのではなく、好きな場所に出せるようにする。あくまで「ドット絵のキャラとドット絵の地形でできた3Dゲーム」であって、マス目のゲームではない。

この試作で確かめたいこと
- エリアを歩いて行き来すると、1つの大陸を探検している感じがするか。
- 細かい段差のある地形で、高さが読みやすく、高さを使って戦えるか。
- 鉄球を好きな場所に出す操作が気持ちよいか。
- 時間で戻る敵と、死んでも戻らない敵が、探検のテンポに合うか。

失敗（動いていても失敗とみなすもの）
- エリアの切り替えが、別々のステージを渡り歩いているように感じる。
- 段差が見た目だけで、戦い方に関係しない（design.md 4章のアンチゴール）。
- どこが何段なのか、登れるのか、ぱっと見て分からない。
- 切り替えのたびに待たされる、同じ敵と何度も戦い直すなど、細かい面倒が多い。

## 2. やること・やらないこと

やること
- 4つのエリア（野営地・岩場・丘陵・奥の森）。今の箱庭の島（area_02）の代わりにする。
- エリアの端の出口（矢印）と、エリアの切り替え。
- 各エリアの、大陸の上での位置と大きさ（後で全体マップを作れる形のデータ）。
- 細かい段差の地形と、高さを読みやすくする描き方。
- 鉄球を、届く範囲のカーソルの位置に、マス目に合わせずに出す。
- 敵の復活を、時間とエリアの行き来で決める。
- 墓石・たき火・門の近道・持ち物の扱いを、エリアをまたいで使う。

やらないこと
- 全体マップの画面（データだけ用意する）。
- 新しい武器、レベルアップ、技能、お店、武器の強化、セーブ。
- 簡単モード、カメラを回している間ゆっくりになる設定。
- 敵にカーソルを重ねると高さに照準が合う機能、ホイールでの高さ指定（design.md 5章。鉄球は目の前に落とすだけなので、まだ要らない）。
- CLAUDE.md の「既知の小さな問題」の修正。

## 3. 作り方（決定：A）

検討した3案：

- **A. 1つのシーンで、エリアを入れ替える**：各エリアの地図・大陸の上での位置・出口をデータで持つ。矢印の端に着いたら、今のエリアの地形と敵を片付けて、次のエリアを作る。プレイヤー・持ち物・墓石・敵の復活時間は、エリアを入れ替えても残る。試作2の「死んでもシーンを読み込み直さない」作り（試作2の作り方B）をそのまま活かせて、エリアを足すのはデータを足すだけ。
- B. 大陸全体を1枚の大きな地図にして、今いる範囲だけを描く：全体マップは作りやすいが、地図が大きくなるほど重く、「エリアごとに切り替わる」感じが出にくい。
- C. エリアごとに別のシーンにして、シーンを切り替える：エリア単位で作りやすいが、切り替えのたびに状態の受け渡しが要り、試作2で決めた「読み込み直さない」作りと合わない。

作り方はユーザーから任されているので、ClaudeがAを選んだ（ユーザーは反対していない）。

## 4. 大陸とエリア

### 4.1 エリアの並べ方

- エリアは1つの大陸の一部として並べる。後で全体マップを作ったとき、違和感なくつながるようにする。
- 各エリアは、大陸の上での位置と大きさを持つ。
- 出口は、となりのエリアの、大陸の上で同じ場所の端とつながる。【Claudeの判断】エリアは大陸の上で重ならない長方形にし、出口でつながる2つのエリアは辺を接して並べる。出口の範囲は、両方のエリアで大陸の上の同じマスになるようにする。こうすると、全体マップはエリアの長方形を並べるだけで描ける。テストで、すべての出口が相手のエリアの出口と重なっていることを確かめる。
- 最初の場所（野営地）から遠いエリアほど、敵も手に入るものも強くなる。
- 新しい武器で開く道（design.md 7章）で、行ける範囲が少しずつ広がる。この試作では新しい武器は作らないので、データとして「この出口は、まだ通れない」を書ける形にだけしておく【Claudeの判断】（門と同じく、閉じた出口として扱えればよい）。

### 4.2 最初の4エリア

```
        [奥の森]  ← 強い敵・強い鉄球
         ↑    ↑
     （門）    │
[岩場] ← [野営地] → [丘陵]
          たき火
```

- 野営地：たき火のある安全なエリア。敵はいない。西に岩場、東に丘陵、北に奥の森への出口。北の出口は門で閉じていて、奥の森の側からしか開けられない（試作2の門の近道と同じ）。
- 岩場：岩と崖が多く、細かい段差が続くエリア。敵1が中心（7.1）。素材と回復アイテムがある。出口は野営地への1つだけ。
- 丘陵：段々の丘と川のあるエリア。敵1が中心（7.1）。北に奥の森への出口。
- 奥の森：木の多い、高低差の大きいエリア。敵が強め。強い鉄球がある。南の門を開けると野営地へ直接戻れる近道になる。
- 一周の流れ：野営地 → 丘陵 → 奥の森 → （門を開ける）→ 野営地。
- 奥の森の敵は、敵2（7.1）が中心。【Claudeの判断】弾を撃つ敵も混ぜる。撃つ敵の弾は試作2の11.1のとおり（同じ高さだけに当たり、崖で止まる）。
- 【Claudeの判断】大きさの目安。画面は横20マス・縦11マスくらいが見えるので、1つのエリアは画面の数枚ぶんにする。
  - 野営地：24×20マスくらい
  - 岩場：40×32マスくらい
  - 丘陵：48×36マスくらい
  - 奥の森：56×40マスくらい
- 【Claudeの判断】大陸の上の位置は、野営地を原点にして、上の図のとおり西・東・北に辺を接して置く。奥の森は、野営地と丘陵の両方の北の辺に接する幅にする。具体的な数は実装者が決めてよい（4.1の「辺を接する」「出口が重なる」を守ること）。
- 【Claudeの判断】各エリアには、エリアに入った直後に名前を画面に2秒ほど出す（「岩場」など）。
- 【Claudeの判断】エリアの中で迷わないよう、また探検の動機になるよう、各エリアに「行けそうで行けない高台」や「回り込むと届く拾いもの」を1つ以上置く。

### 4.3 エリアの端と出口

- エリアの端まで行くと、何もないが止まる（見えない壁）。
- 矢印で強調されている端まで行くと、となりのエリアに切り替わる。
- 【Claudeの判断】エリアの端の見た目。地形はエリアの長方形のふちまで続き、ふちでは箱庭のように土と岩の断面が下へ伸びて見える（試作2の島のふちと同じ描き方）。その外は暗い背景で何も描かない。エリアの中に、試作2のような「島の外」の空白は作らない（大陸の一部なので、地面はふちまで続く）。崖の裂け目の奈落はエリアの中に置いてよい。
- 【Claudeの判断】出口の見た目。出口のマスの地面に、外向きの矢印を描く（ゆっくり点滅させる）。出口の範囲は2〜4マス幅にする。出口の前は、プレイヤーが立てる平らな地面にする。
- 【Claudeの判断】切り替えの流れ。
  1. プレイヤーが出口のマスから、さらに外へ歩こうとすると切り替えが始まる（ふちに立っただけでは切り替わらない。うっかり切り替わらないように）。
  2. 画面を0.2秒ほどで暗くし、今のエリアの地形・敵・弾・鉄球（地面にあるもの）を片付けて、次のエリアを作る。
  3. プレイヤーを、次のエリアの対応する出口の、1マス内側に置く。出口の幅の中の位置（左右のずれ）は保つ。向きも保つ。
  4. 画面を0.2秒ほどで明るくする。
- 【Claudeの判断】地面に置いたままの鉄球は、エリアを出ると手元に戻る（拾い直しに戻らなくて済むように）。
- 【Claudeの判断】出口から入った所の周り（3マス以内）には、敵を置かない。敵もそこへは歩いて入らない。切り替えた瞬間に体当たりされないようにするため。

## 5. 高さ

- 高さは、システム的にもっとこまめに変わってほしい。
- 今の島は少し見にくい。

### 5.1 地形の作り方

- 【Claudeの判断】広い平地を減らし、1段の小さな段差が細かく続く地形にする。目安として、同じ高さが続く平らな所は、だいたい8×8マス以内にする（野営地の広場は除く）。
- 【Claudeの判断】2段以上の崖（登れないが飛び降りられる段差）は所々に置き、鉄球を上から落とせる場所にする。4段以上の崖（飛び降りられない）は、道を分ける所にだけ使う。
- 【Claudeの判断】高さの範囲は0〜8段くらいにする（試作2は0〜5）。1段＝8pxは変えない（design.md 15章）。
- 【Claudeの判断】段差には「登れる1段の道」を必ず用意し、どこからでも目で見て登り道を探せるようにする。
- 地図は試作2と同じく、`tools/island_map/` を土台にしたPythonスクリプトで作る（エリアごとに作れるように直す）。経路の長さ、閉じ込められるくぼみがないこと、出口どうしがつながっていることを確かめる。
- 【Claudeの判断】経路の長さの目安（試作2の「歩いて1分以上」を引き継ぐ）。たき火から丘陵を通って奥の森の強い鉄球まで、歩いて1分半以上。奥の森で門を開けた後は、強い鉄球のあたりから野営地のたき火まで30秒以内で戻れる。墓石を取りに行く歩き直しが、長すぎず短すぎないようにするため。

### 5.2 高さの見やすさ

- 【Claudeの判断】描き方で高さを読みやすくする。
  - 段の上のふち（隣が低い辺）に、1pxの明るい線を引く。
  - 側面は、下へ行くほど暗くする。何段ぶんの側面かが、色の帯で数えられるようにする（1段ごとに、色が少し変わるか細い線が入る）。
  - 地面の上の色を、高い所ほど少し明るくする（色数は増やしすぎない）。
  - プレイヤーと敵の足元に、小さな影を落とす。
- 細かい色や線の太さは、実際の画面を見て決める（実装者に任せる）。

## 6. 鉄球の出し方

- 鉄球などのアイテムは、マス目に合わせずに、好きな場所に出せるようにする。
- 届くのは、手の届く範囲だけ（ユーザーがA案を選んだ）。【Claudeの判断】体の中心から1.5マス（24px）以内。カーソルがそれより遠いときは、カーソルの方向の、届く一番遠い所に出す。
- これで design.md 7章の「鉄球：目の前に落とすことしかできない」は、「手の届く範囲の、好きな場所に落とす」に変わる。高い所から真下へ落とすには、崖のふちまで近づく必要がある、という危なさは残す。
- 【Claudeの判断】落ちる場所の決め方。
  - カーソルが指している地面の点（カメラの向きと、地面の高さを考えて、画面の点から地面の点を求める）を狙う。いま狙っている地面の点に、影の印を出す（今と同じ）。
  - 鉄球はその点に、マス目に合わせずに落ちる。落ちる先の高さは、その点があるマスの高さ。
  - ダメージ＝プレイヤーが立っている高さ − 落ちた先の地面の高さ ＋1（最低1）。強い鉄球は＋2（最低2）。今の式と同じ。自分より高い所に置いたときも最低のダメージになる。
  - 落とせないのは、落ちる点が水・奈落・壁（木・岩・閉じた門など）の上のとき。墓石の上には落とせて、墓石が壊れる。
  - 当たり：落ちた点から一定の半径（【Claudeの判断】8px）の中にいて、落ちた先と同じ高さに立っている敵に当たる。墓石は、半径の中に墓石のマスがかかれば壊れる。
- 拾い直しは今と同じく、上を歩くと拾う（【Claudeの判断】体の中心が鉄球から6px以内）。
- 登れない所に落ちた鉄球が、少しして足元に戻る仕組みは今のまま。
- 回復アイテムは、今と同じくその場で使う（場所は選ばない）。
- プレイヤーと敵の位置は、今と同じくマス目に縛られない。【Claudeの判断】ただし地形の高さと壁はマス単位のまま（地形はドット絵のボクセルのマスでできているため）。

## 7. 敵

- 倒した敵は、時間がたつと復活する。
- 時間は、そのエリアにいる間も数える。ただし、敵が戻るのは、プレイヤーが一度別のエリアへ行ってから（今いるエリアで、目の前に急に湧くことはない）。
- 死んでも、敵は復活しない。これは試作2の「死ぬと敵は全員復活する」（試作2の4.7）を取り消す。
- 【Claudeの判断】復活するまでの時間は、敵を倒してから5分（ゲームの中の時間。インベントリを開いて止まっている間は数えない）。数値は仮。
- 【Claudeの判断】エリアに入ったとき、倒されていない敵と、復活の時間を過ぎた敵は、初期の位置・向き・最大体力で置き直す。エリアを出たときの体力や位置は覚えない。
- 【Claudeの判断】死んだときは、プレイヤーが野営地のたき火へ戻るので、死んだエリアからは出たことになる。死んだエリアに戻ったとき、5分たっていない敵は倒れたまま。
- 【Claudeの判断】死んだときの弾は今と同じくすべて消える。
### 7.1 敵の種類

- 敵1：弱いので段差を登り降りできない（平らな所だけを歩く）。体力1、体当たりだけ（試作2の11.2）。
- 敵2：近接攻撃を持つ。体力2。1段の段差を登れる（降りるのも1段まで【Claudeの判断】）。2段以上の崖は越えない。
- 【Claudeの判断】敵2の近接攻撃。ふだんは往復して歩き、同じ高さか1段違いで3マス以内にプレイヤーがいると近づいてくる。体の前1マスほどに近づくと、0.5秒ためて（体が光る合図）から前を叩く。当たると1ダメージ。ためている間に離れるか、2段以上の段差の上に逃げればよけられる。体当たりのダメージはない。
- 【Claudeの判断】弾を撃つ敵（体力1、平らな所だけ）は奥の森にだけ置く。
- 【Claudeの判断】置き方：岩場と丘陵は敵1が中心で、敵2を少し。奥の森は敵2と弾を撃つ敵が中心。
- 【Claudeの判断】敵1は平らな所しか歩けないので、敵1を置く所には、ほかより広めの平地（6×6マス以上）を作る。5.1の「平らな所は8×8マス以内」はそのまま守る。

## 8. 死と取り返し（試作2から引き継ぐもの）

- 死んだら、野営地のたき火から再開する。体力は最大。
- 墓石は世界に1つだけ。死んだエリアの、死んだ場所に残る。
- 持ち物の扱い（お金は半分、素材・回復・強い鉄球は墓石へ、普通の鉄球と経験値は手元）は試作2の4.1のまま。
- 一度拾ったものは、死んでも復活しない。
- 開けた門は、死んでも開いたまま。
- 【Claudeの判断】墓石の位置は、エリアの名前とそのエリアの中のマスで覚える。墓石があるエリアに入ると、墓石が描かれる。
- 【Claudeの判断】墓石のあるエリアが分からなくならないように、画面の上の持ち物の行の横に「墓石：丘陵」のように出す。エリアの中での場所の矢印は付けない（試作2の4.2と同じ考え）。
- 落下死（奈落）のときの墓石の置き方は、試作2の4.3のまま。

## 9. 画面の表示（UI）

- 今の日本語の表示（体力・持ち物・手に持つアイテム・操作の説明）はそのまま。
- 【Claudeの判断】足すもの：エリアに入ったときの名前（4.2）、墓石のあるエリア（8章）。
- 【Claudeの判断】なくすもの：ゴールの旗と「クリア」の表示。

## 10. 決まりごと

- 新しいルール（エリアのデータ、出口のつながり、敵の復活の時間、鉄球の自由な落とし場所など）は `scripts/rules/` に RefCounted クラスとして書き、先にGUTで失敗するテストを書いてから実装する（CLAUDE.md）。
- 今のテストは通ったままにする。試作2の島（area_02）専用のテストは、新しいエリアのテストに置き換えてよい。
- コメントとコミットメッセージは日本語。UIの文字は日本語。

## 11. 実装者に任せること

- クラスの分け方と名前、エリアのデータの持ち方（GDScriptの定数か、別のデータファイルか）。
- 各エリアの地形の細かい形、敵と拾いものの数と位置（4章と5章の条件を守ること）。
- 色・線・影の細かい見た目（5.2）。
- 【Claudeの判断】試作2の島（`scenes/area_02.tscn` と `area_02.gd`）は、新しいエリアの仕組みに置き換えて消してよい。試作1（`stage_01`）は残し、鉄球を落とす場所は「目の前のマスの中心」を渡して今と同じに動くようにする。
- 新しいメインシーンの名前（たとえば `scenes/field.tscn`）。

## 12. design.md に反映すること（設計が承認されたら）
